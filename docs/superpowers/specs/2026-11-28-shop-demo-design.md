# Демо конструктора для цветочного магазина — решения

Итог грилинга 28.11.2026. Продукт в перспективе — SaaS для цветочных магазинов. Этот документ описывает только первый шаг: демо для 1–2 знакомых магазинов.

## Продукт (долгосрочно)

- Клиент — цветочный магазин, платит фиксированную подписку. Процент с заказа появится только вместе с онлайн-оплатой в конструкторе.
- Покупатель открывает страницу магазина по ссылке из био Instagram или из WhatsApp.
- После «Заказать» открывается чат WhatsApp с магазином, где уже набран состав и сумма. Оплата и доставка остаются в переписке.
- Каталог и цены магазин ведёт сам в админке с телефона. В демо её нет.
- Главное требование — реализм: собранный букет должен быть похож на то, что человек получит. Основа — коллаж из фото общей библиотеки цветов. В демо остаются текущие SVG-рисунки.
- Успех пилота: магазин сам соглашается платить после бесплатного периода.
- Ценность для магазина не проверена — это главный риск.

## Демо (этот шаг)

1. Каталог разделён на **библиотеку** (как позиция выглядит) и **магазин** (что есть в наличии и почём). Магазин хранится в одном файле конфигурации, его правит разработчик.
2. Валюта — тенге (₸), все тексты на русском.
3. Кнопка **«Заказать в WhatsApp»** открывает чат с номером магазина, сообщение заполнено: состав, открытка, итог.
4. В сообщении есть **ссылка на макет**: флорист открывает её и видит тот же букет, что собрал покупатель. Это закрывает риск «собрали не то».
5. Без сборки и зависимостей, страница работает и с GitHub Pages, и как локальный файл.
6. Публикация на GitHub Pages, ссылка в био магазина.

## Вне демо

Админка, мультиарендность, фото-коллаж, онлайн-оплата, аналитика заявок — нажатия «Заказать» на пилоте считает сам магазин по входящим чатам.
