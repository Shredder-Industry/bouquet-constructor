# Реалистичное фото букета через Gemini — дизайн

## Зачем
Макет в конструкторе (SVG-сцена `#stage`) выглядит нереалистично. Клиенту нужно увидеть,
как собранный букет будет выглядеть вживую, чтобы увереннее заказать.

## Цели / не-цели / анти-цели
- Цель: по кнопке получить фотореалистичный кадр именно собранного букета (те же цветы,
  цвета, упаковка, примерная композиция).
- Не-цель: точное совпадение количества стеблей; редактирование фото; хранение истории.
- Анти-цель: красивая картинка, не похожая на сборку; ключ API в браузере.

## Подходы
1. **Gemini image (img2img) — выбран.** Скриншот сцены + список цветов → фото. Держит
   композицию, дёшево, быстро.
2. Flux Kontext (fal/Replicate) — сопоставимо, хуже работает с образцами, платно с нуля.
3. Локальный SDXL img2img — бесплатно, но только на Mac автора; не для клиентов.
Kimi отпал: не генерирует изображения.

## Как устроено
- **Клиент:** кнопка «Показать вживую» (рядом с макетом и в экране заказа).
  SVG `#stage` растеризуется в PNG через `<canvas>` (картинки цветов — того же origin,
  canvas не «испачкается»). Отправляется `POST /api/realistic` с PNG (base64) и
  составом букета (названия цветов, количество, упаковка) из текущего состояния.
- **Промпт** собирается на сервере: «превратить макет в студийное фото реального букета,
  сохранить расположение и цвета цветов, упаковку: …, состав: …, нейтральный фон».
- **Сервер:** одна serverless-функция (`api/realistic.js`, Vercel), ключ `GEMINI_API_KEY`
  в env. Валидирует вход (размер PNG ≤ ~2 МБ, состав — массив известных id), зовёт Gemini,
  возвращает картинку. Простой лимит запросов на IP.
- **UI результата:** модальное окно со спиннером → фото, подпись «Изображение создано ИИ,
  реальный букет может немного отличаться», кнопки «Ещё вариант» и «Заказать».
- **Ошибки:** понятное сообщение и кнопка «Повторить»; конструктор продолжает работать.
- **Локально:** `vercel dev` вместо `python -m http.server`; `.env.example` с пустым ключом.

## Решения автора кода (можно поправить)
- Хостинг функции — Vercel (проект статический, деплоится туда без перестройки).
- Конкретная модель Gemini для изображений — актуальная на момент реализации.
- Фото цветов-образцы в запрос пока не отправляем; добавим, если цвета будут «плыть».
- Логика промпта и валидации — в отдельном модуле с unit-тестами (`node --test`).

## Изменение 2026-11-28
У Gemini бесплатная квота на генерацию изображений равна 0, поэтому провайдер заменён на Cloudflare Workers AI, FLUX.2 [dev] (`CF_ACCOUNT_ID`, `CF_API_TOKEN`). Выход 512×640, снимок 512 px в ширину, чтобы уложиться в бесплатные 10 000 нейронов в день.

Второе изменение: FLUX.2 [dev] на бесплатном лимите давал около 3 фото в день и выглядел ненатурально. Пользователь проверил Seedream 5.0 на fal.ai, результат понравился, поэтому провайдер теперь `bytedance/seedream/v5/flash/edit` ($0.027 за фото, ключ `FAL_KEY`), выход 1024×1280, снимок макета 768 px, промпт описывает сцену как фотограф.

Третье изменение: по сравнению на одном букете пользователь выбрал на время Seedream 5.0 Pro и 5.5, финально останется одна. Генерация через очередь fal (POST ставит задачи, GET опрашивает), набор моделей в `FAL_MODELS`, фото показываются рядом.
